Fast Fashion Dashboard API

Cette documentation reflète désormais une spec OpenAPI plus riche : schémas, paramètres, réponses, sécurité Bearer par endpoint protégé, endpoints publics séparés pour /openapi.json et /healthz, métadonnées sûres sur l’egress proxy / la politique ASOS côté S3 (max 2 en direct, cap proxy configurable avec défaut à 8), et sélection intelligente des candidats d’upload via selection_mode (pending par défaut, pending_only, partial, all).

Accès & sécurité

Important
  • /openapi.json est public pour les outils d’intégration et de génération de clients.
  • /api/openapi.json reste disponible comme alias de compatibilité.
  • /healthz est public pour Dokploy / Traefik / health checks.
  • Les endpoints métier /api/* exigent Authorization: Bearer <token> quand FAST_FASHION_API_TOKEN est défini.
  • Les endpoints JSON S3 (/api/s3/*) acceptent aussi ce Bearer token pour l’automatisation distante; la page HTML /s3 continue d’utiliser son cookie d’accès court vécu pour l’UI.
  • La configuration S3 effective est désormais lue depuis les variables d’environnement du serveur (AWS_BUCKET, AWS_PREFIX, AWS_ENDPOINT_URL, AWS_URL) au lieu d’être persistée via l’API.
  • Si TELEGRAM_BOT_TOKEN et TELEGRAM_CHAT_ID sont tous les deux définis, le backend envoie une notification Telegram simple à la fin de n’importe quel job S3 (upload, migration, cleanup).
  • La page /s3 suit désormais un déverrouillage en deux temps quand l’API est protégée : validation du token Bearer API d’abord, puis mot de passe admin S3 pour obtenir le cookie de session S3.
  • Le backend peut aussi activer un proxy d’egress applicatif pour les fetchs HTTP(S) tiers via FAST_FASHION_PROXY_HOST, FAST_FASHION_PROXY_PORT, FAST_FASHION_PROXY_LOGIN et FAST_FASHION_PROXY_PASSWORD. Ces secrets restent côté serveur; l’API n’expose qu’un état dérivé sûr.
  • Quand ce proxy est activé, le cap de concurrence ASOS côté upload est configurable via FAST_FASHION_ASOS_PROXY_MAX_CONCURRENCY (défaut 8, plafond global 24).
  • La page /s3 sépare maintenant trois familles de jobs : upload, migration d’URL, cleanup d’état S3.
  • Chaque famille suit le même cycle : preview persisté en dry_run=true, lancement réel en dry_run=false, arrêt, détail, historique.
  • Le dashboard HTML peut rester public même si l’API est privée.

Endpoints API principaux

Protégés par Bearer token
GET/api/datasets

Retourne les métadonnées des datasets exposés. Peut aussi filtrer un dataset précis.

GET/api/categories

Liste paginée des catégories stables d’un dataset. Supporte désormais savedOnS3=true pour ne garder que les catégories ayant au moins un produit sync sur S3, avec image_url qui préfère une image S3 représentative.

GET/api/categories/{slug}

Détail d’une catégorie par slug stable. Supporte aussi savedOnS3=true avec la même logique de filtrage et de préférence d’image S3.

GET/api/products

Liste paginée des produits uniquement. Les catégories sont désormais récupérées séparément via /api/categories.

GET/api/products/{goods_id}

Détail produit unique, avec payload dashboard legacy + payload resource stable dans la même réponse.

Familles de jobs S3 protégées

Routes admin séparées
GET/api/s3/upload-jobs
POST/api/s3/upload-jobs

Historique et création des jobs d’upload. Le preview passe par dry_run=true. Les créations acceptent aussi un source_filter optionnel pour cibler un produit déterministe (id exact ou fragment insensible à la casse du nom / URL / image source), ainsi qu’un selection_mode : pending (défaut, unsynced + partiels), pending_only (produits non synchronisés seulement), partial (réparation des partiels seulement), ou all (rescan complet). L’état du job expose aussi excluded_complete_count pour rendre visible le nombre de produits déjà complets exclus avant traitement, et les jobs terminés peuvent déclencher une notification Telegram serveur quand les variables d’env dédiées sont configurées.

GET/api/s3/url-migration-jobs
POST/api/s3/url-migration-jobs

Historique et création des jobs de migration des anciennes URLs s3:// vers AWS_URL.

GET/api/s3/state-cleanup-jobs
POST/api/s3/state-cleanup-jobs

Historique et création des jobs de reset des états S3 obsolètes.

GET/api/s3/jobs/{job_id}
POST/api/s3/jobs/{job_id}/cancel

Détail paginé et annulation partagés. Les payloads exposent désormais job_family et dry_run.
